# دليل عرض مشروع التخرّج

## عرض مقترح خلال 8–10 دقائق

1. **المشكلة:** قراءة شرح البرمجة دون تطبيق أو تفسير للخطأ تجعل التعلم سطحيًا.
2. **الحل:** درس من مصدر معروف، ثم تدريبات متدرجة مع نتيجة وتفسير، ضمن قصة إعادة تشغيل مدينة.
3. **المصدر:** افتح قارئ الكتاب، ثم درسًا وافتح الصفحة الأصلية المرتبطة به. وضّح الفرق بين النص الأصلي والشرح المبسّط.
4. **واجهة عربية دقيقة:** بدّل اللغة، واشرح أن الكود يبقى LTR بينما الشرح العربي RTL.
5. **التفاعل:** افتح فصل بيئة بايثون ثم درس الطباعة. جرّب توقّع الناتج وإكمال الرمز وترتيب السطور.
6. **خطأ مفيد:** في محرر الكود اكتب `print(missing_name)`، وأظهر تفسير NameError، ثم اكتب الحل الصحيح.
7. **اللعبة:** أظهر إضاءة محطة وزيادة XP، ثم كرر الحل لتوضيح أن النقاط لا تتضاعف.
8. **البيانات:** أضف ملاحظة، ثم افتح الإنجازات أو مراجعة الأخطاء. أظهر تصدير JSON/CSV.
9. **المعمارية:** Python للخادم وقاعدة SQLite، وPyodide داخل Web Worker لتشغيل كود الطالب بعيدًا عن ملفات الخادم.
10. **الجودة والحدود:** شغّل الاختبارات، واعرض حدود التقييم المتصفحي وخطة التطوير قبل الاستضافة العامة.

## أسئلة متوقعة

**لماذا لم تستخدم API للذكاء الاصطناعي؟** لضمان أن المسار الأساسي يعمل محليًا، مع شروح محددة يمكن مراجعتها. الروبوت شخصية تعليمية، وليس نموذج لغة.

**كيف تختلف عن ملف PDF؟** كل مفهوم مرتبط بممارسة وتصحيح ومسار تقدّم، ويمكن كتابة Python وتنفيذه.

**هل العدد الكبير يعني أسئلة مختلفة كليًا؟** لا؛ لكل درس برمجي أربعة أنماط تدريب على الفكرة، وبعضها يعيد استخدام المثال. العدد يعكس الأنشطة لا مسائل مستقلة غير متكررة.

**هل اختبار الكود مقاوم للغش؟** لا. النسخة المحلية تدريبية؛ الامتحانات الرسمية تحتاج تقييمًا خادميًا معزولًا واختبارات متعددة.

**هل كل نص مأخوذ حرفيًا؟** صور الصفحات والـPDF تحفظ الأصل حرفيًا. ملخصات الدروس مصاغة من المفاهيم، والتمارين جديدة ومعلّمة بذلك.
